# Прогнозирование следующего товара в сессии (GRU и NARM) с детекцией аномальных сессий

Проект решает задачу рекомендаций на основе сессий: по последовательности товаров, которые пользователь просмотрел в текущей сессии интернет-магазина, нужно предсказать товар, который он откроет следующим. Дополнительно реализована детекция аномальных сессий и проверено, как очистка данных влияет на качество моделей.

## Что реализовано

- Подготовка данных: сборка сессий из событий, очистка, разбиение на обучающую, валидационную и тестовую выборки
- Детекция аномальных сессий двумя методами: правила на пороговых признаках и Isolation Forest
- Две нейросетевые модели на PyTorch: GRU и NARM (GRU + механизм внимания)
- Оценка качества метриками Recall@K и MRR@K, сравнение «до» и «после» удаления аномальных сессий

## Данные

Используется открытый набор [RetailRocket Ecommerce Dataset](https://www.kaggle.com/datasets/retailrocket/ecommerce-dataset) (Kaggle).

Используемые файлы:

| Файл | Для чего используется |
|---|---|
| `events.csv` | события пользователей (просмотр, корзина, покупка), основа для сессий |
| `item_properties_part1.csv`, `item_properties_part2.csv` | свойства товаров |
| `category_tree.csv` | дерево категорий, признаки для детекции аномалий |

В работе моделируются только просмотры товаров, потому что они составляют подавляющее большинство событий.

## Как устроено

1. **Предобработка.** События сортируются по пользователю, времени и товару. Новая сессия начинается при смене пользователя или при паузе между событиями больше часа. Остаются просмотры товаров, подряд идущие повторы одного товара удаляются (230 228 записей). Данные приводятся к виду `SessionId, ItemId, Time` и делятся на 3 выборки.
2. **Детекция аномалий.** Для каждой сессии считаются признаки поведения, затем применяются два метода:
   - правила: порог по 99-му (или 1-му) перцентилю для признаков ;
   - Isolation Forest из scikit-learn (200 деревьев).

   Сессия считается сильной аномалией, только если её отметили оба метода. На выходе получаются очищенные версии трёх выборок.
3. **GRU.** Товары превращаются в векторы (Embedding, размерность 224), затем обрабатываются ячейкой GRU; по скрытому состоянию сессии вычисляются оценки товаров-кандидатов. Словарь товаров строится только по обучающей выборке, неизвестные товары в валидации и тесте отбрасываются. Лучшая модель выбирается по Recall@20 на валидации.
4. **NARM.** Отдельный адаптер преобразует сессии в пары «префикс сессии, следующий товар». Модель сочетает рекуррентную обработку и механизм внимания, поэтому по-разному учитывает товары внутри сессии. Архитектура, параметры обучения и метрики те же, что и в эксперименте с GRU, отличаются только входные файлы (с очисткой и без).

## Результаты

Метрики на тестовой выборке:

| Метрика | GRU до | GRU после | NARM до | NARM после |
|---|---|---|---|---|
| Recall@5 | 0,256 | 0,266 | 0,261 | 0,287 |
| Recall@10 | 0,350 | 0,363 | 0,352 | 0,390 |
| Recall@20 | 0,446 | 0,456 | 0,445 | **0,485** |
| MRR@10 | 0,162 | 0,166 | 0,170 | 0,183 |
| MRR@20 | 0,168 | 0,173 | 0,177 | **0,189** |

«До» и «после» означают обучение на данных до и после удаления аномальных сессий.

Выводы:
- удаление аномальных сессий улучшило метрики обеих моделей, у NARM эффект заметнее;
- по Recall@20 модели до очистки почти одинаковы, но NARM лучше ранжирует (выше MRR);
- лучший результат показала NARM на очищенных данных.

Ограничения: использованы только просмотры товаров (без корзины и покупок), один датасет, аномалии выделялись без разметки, поэтому проверить точность самой детекции нельзя.
